# px-epyc host files (installed 2026-10-08/09)

| File | Installed at | What |
|---|---|---|
| `gpu-5060ti-powercap.service` | `/etc/systemd/system/` (enabled) | Caps all four RTX 5060 Ti core clocks at 2600 MHz (`nvidia-smi -lgc 210,2600`) at boot - summer thermals; they throttle ~87 C and can drop off the bus at 89-90 C. |
| `gpu-thermal-recorder` + `.service` | `/usr/local/sbin/`, `/etc/systemd/system/` | ONE long-running `nvidia-smi -lms 1000` process (never one call per poll); logs 5060 Ti temps at 1 s while utilisation > 75 % to `/var/log/gpu-thermal/`. |
| `gpu-thermal-recorder.json` | `/etc/` | Per-card labels by UUID (cooling layout: #0/#3 have a 40 mm server fan at the heatsink end, #1 fan on heatsink, #2 PNY vertical fins). |
| `gpu-thermal-report` | `/usr/local/sbin/` | Summarises the recorder logs (peak / time above thresholds per card). |
| `zramswap` | `/etc/default/zramswap` | 32 GiB zstd zram swap, priority 100 - headroom for ai-epyc (CT176, RAM lowered to 160 GB). |

Re-install: copy each file to its path, `systemctl daemon-reload`, `systemctl enable --now <unit>`; zram via `systemctl restart zramswap`.
| `usr/local/sbin/ailab-model-cache-warm`, `etc/systemd/system/ailab-model-cache-warm.service` (enabled), `etc/systemd/system/ailab-ai-ct-failsafe.{service,timer}` (timer enabled), `etc/ailab/model-cache-warm.json` | 2026-10-31 | CT176 ai-epyc: Refills the host's model-cache RAM drive (`/mnt/model-cache`, tmpfs) after a boot and THEN starts the AI container (onboot set to 0; original onboot/startup kept in `etc/ailab/model-cache-warm.json` and in the CT conf comment). Copies on the HOST (tmpfs pages are charged to the writer's memcg): the AI-Lab cacher manifest (`/etc/ailab/model-cache-manifest.json`, pushed by ai.js with every usage-file write) from the NAS, and the image model service's RAM tier from its saved state (CT disk `/var/lib/ailab-modelsvc/state.json`) + its persistent tier only, with index.json + the saved quota config, owned by the CT's root. `<dst>.part` + byte check, the shared 5 % reserve, the RAM tier within its scaled quotas; `<drive>/.ailab-warming` makes the AI-Lab reconciler skip the drive meanwhile. Starts the CT when warm or at cap_s (900 s), always: try/finally, the unit's ExecStopPost (`--ensure-started`), and `ailab-ai-ct-failsafe.timer` (25 min after boot; falls back to plain pct if the script is broken). Container starts happen only within boot_window_s (1 h) of boot, so a manual run never starts a CT someone stopped. Test: `--dry-run [--drive DIR]`, `--warm-only --drive <scratch tmpfs> --max-gb N`. Undo: `pct set <vmid> --onboot 1`, disable both units. claude1, 2026-10-31. |
| `usr/local/sbin/ailab-model-cache-warm` v2 + `etc/ailab/model-cache-warm.json` (disk_root, nas_mbps 300) | 2026-10-31 (disk first) | The host side of the model caches (Travis's rule: a model that goes into RAM or onto a GPU first gets a LOCAL disk copy and is loaded / refilled from it; the NAS only for files missing or stale on disk, write-through, one fill at a time per host via flock, capped at nas_mbps). AI-Lab's copy queue calls `--fill <cacheDir>` (disk from RAM / NAS, then RAM from disk; per-file reuse of local copies; `<dst>.part` for a new copy, per-file `.part` when refreshing a stale one; both reserves), its reconciler reads `--status-json` (disk vs NAS and RAM vs disk, file by file: names, sizes, mtimes). Boot: phase 1 disk -> RAM only, then the AI CT starts, then the entries that need the NAS in a background transient unit `ailab-model-cache-nasfill`. claude1. |
